# 007: Create init skill

## Implementation Notes

This is the most complex work item. The skill file is markdown with YAML frontmatter that Claude Code interprets and follows as instructions.

### Frontmatter

```yaml
---
description: "Detect project tech stacks and generate tuned permission allowlists and sandbox configuration"
user-invocable: true
argument-hint: "[--no-sandbox]"
---
```

### Skill Structure (four phases)

#### Phase 1: Discovery

Instructions for Claude to:

1. Use Glob to find all `*.json` in `${CLAUDE_PLUGIN_ROOT}/stacks/`
2. Use Glob to find all `*.json` in `.claude/guardrail/stacks/` (project overrides)
3. For same-name files, project versions replace plugin versions entirely
4. Read each stack JSON file
5. For each stack (except `_base`), use Glob to check project directory for `detect.files` patterns
6. Mark stacks where at least one pattern matched (if `detect.match` is `"any"`) or all patterns matched (if `"all"`)
7. Read all rule module JSONs from `${CLAUDE_PLUGIN_ROOT}/rules/` and `.claude/guardrail/rules/`
8. Read sandbox template from `${CLAUDE_PLUGIN_ROOT}/sandbox/default.json`

#### Phase 2: Interactive Menu

Instructions for Claude to present:

```
Detected stacks:
  [x] python (pyproject.toml found)
  [x] shell (Makefile found)

Available stacks:
  [ ] node
  [ ] rust
  [ ] go

Rule modules:
  [x] git (recommended)
  [x] web (recommended)
  [ ] docker
  (auto-included: mcp-ideate, mcp-cyberbrain)

Sandbox: [x] enabled (auto-allow mode)
```

User can toggle selections. Instruct Claude to ask: "Adjust any selections, or proceed with these?"

#### Phase 3: Merge

Instructions for the merge algorithm:

1. Start with `_base.json` — always included
2. For each selected stack: union `permissions.allow`, union `permissions.deny`, merge `sandbox` fields
3. For each selected rule (including auto:true rules): union `permissions.allow`, union `permissions.deny`
4. If sandbox enabled: start from `sandbox/default.json`, union `sandbox.network.allowedDomains` from all selected stacks, union `sandbox.filesystem` fields
5. Deduplicate all arrays
6. Sort `allow` and `deny` arrays alphabetically

#### Phase 4: Write

Instructions for:

1. Check git repo: run `git rev-parse --git-dir 2>/dev/null`
   - Success: target = `{git-root}/.claude/settings.local.json`
   - Failure: ask user for target path, default to `{cwd}/.claude/settings.local.json`
2. If target file exists:
   - Read and parse it
   - Extract current `permissions` and `sandbox` keys
   - Show diff: what rules would be added, removed, or changed
   - Ask: "Merge (add new rules to existing) or Replace (overwrite permissions + sandbox)?"
   - If replace: create backup at `settings.local.json.bak`
   - Preserve all non-permissions, non-sandbox keys (env, hooks, plugins, etc.)
3. If target does not exist:
   - Create `.claude/` directory if needed
4. Show final JSON output
5. Ask for explicit confirmation: "Write this configuration? (yes/no)"
6. Write using the Write tool

### Edge cases to handle in skill instructions

- Empty project directory (no stacks detected): still write `_base` + selected rules
- Existing settings with non-JSON content: warn user, do not overwrite
- `.claude/guardrail/` directory doesn't exist: skip project overrides silently
- `_base.json` missing from plugin: error — this is a required file
