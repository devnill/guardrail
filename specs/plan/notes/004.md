# 004: Create node.json, rust.json, go.json, shell.json stacks

## Implementation Notes

### node.json

Detection: `package.json`, `tsconfig.json`, `*.js`, `*.ts`, `*.jsx`, `*.tsx`, `yarn.lock`, `pnpm-lock.yaml`
Allow: `node`, `npm`, `npx`, `yarn`, `pnpm`, `jest`, `vitest`, `eslint`, `prettier`, `tsc`, `tsx`, `next`, `vite`, `webpack`, `esbuild`, `turbo`
Network: `registry.npmjs.org`, `registry.yarnpkg.com`

### rust.json

Detection: `Cargo.toml`, `Cargo.lock`, `*.rs`
Allow: `cargo`, `rustc`, `rustup`, `clippy`, `rustfmt`, `cargo-watch`, `cargo-nextest`
Network: `crates.io`, `static.crates.io`

### go.json

Detection: `go.mod`, `go.sum`, `*.go`
Allow: `go`, `gofmt`, `goimports`, `golint`, `golangci-lint`, `staticcheck`
Network: `proxy.golang.org`, `sum.golang.org`

### shell.json

Detection: `Makefile`, `*.sh`, `justfile`, `Taskfile.yml`
Allow: `make`, `just`, `bash`, `sh`, `shellcheck`, `shfmt`
No sandbox network (shell tools don't need external package registries).

### Common patterns across all four

- All use `detect.match: "any"`
- All permission entries use `Bash(tool:*)` format
- None include deny rules (covered by `_base.json`)
- All are self-contained with no references to other stack files
