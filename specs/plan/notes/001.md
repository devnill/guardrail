# 001: Create plugin manifest and CLAUDE.md

## Implementation Notes

### plugin.json

Follow the pattern from beepboop and ideate plugins. The `skills` array must reference the exact paths where SKILL.md files will be created:

```json
{
  "name": "guardrail",
  "version": "1.0.0",
  "description": "Automates permission allowlists and sandbox configuration for Claude Code projects",
  "author": { "name": "Dan Singer" },
  "license": "MIT",
  "skills": [
    {
      "name": "init",
      "path": "skills/init/SKILL.md",
      "description": "Detect project stacks and generate tuned permission + sandbox config"
    },
    {
      "name": "audit",
      "path": "skills/audit/SKILL.md",
      "description": "Analyze existing permission rules, find consolidations and risks"
    }
  ]
}
```

Note: The plugin.json schema may vary from the examples above. Check the ideate and beepboop plugin.json files for the exact field names and structure used by the marketplace. Match that structure.

### marketplace.json

Follow the pattern from ideate's `.claude-plugin/marketplace.json`:

```json
{
  "name": "guardrail-marketplace",
  "owner": { "name": "Dan Singer" },
  "metadata": {
    "description": "Guardrail plugin marketplace",
    "version": "1.0.0"
  },
  "plugins": [
    {
      "name": "guardrail",
      "source": "./",
      "description": "Automates permission allowlists and sandbox configuration for Claude Code projects",
      "version": "1.0.0"
    }
  ]
}
```

### CLAUDE.md

Keep this minimal — orientation only, not behavioral instructions. Contents:

- One sentence describing guardrail's purpose
- Data file locations: `${CLAUDE_PLUGIN_ROOT}/stacks/`, `${CLAUDE_PLUGIN_ROOT}/rules/`, `${CLAUDE_PLUGIN_ROOT}/sandbox/`
- Project override location: `.claude/guardrail/stacks/`, `.claude/guardrail/rules/`
- Reminder: skills read JSON data files at runtime — never hardcode permission lists in skill markdown
