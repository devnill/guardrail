# 005: Create rule modules (git, web, docker, mcp-ideate, mcp-cyberbrain)

## Implementation Notes

### git.json

```json
{
  "name": "git",
  "description": "Git version control operations",
  "permissions": {
    "allow": ["Bash(git:*)"],
    "deny": [
      "Bash(git push --force:*)",
      "Bash(git push -f:*)",
      "Bash(git reset --hard:*)",
      "Bash(git clean -f:*)",
      "Bash(git checkout -- .:*)"
    ]
  }
}
```

Note: `Bash(git:*)` is broad. The deny rules are critical safety nets for destructive git operations. Claude Code's deny-always-wins semantics ensure these cannot be bypassed by the allow rule.

### web.json

```json
{
  "name": "web",
  "description": "Web search and documentation fetching",
  "permissions": {

```

### docker.json

```json
{
  "name": "docker",
  "description": "Docker and container operations",
  "permissions": {
    "allow": [
      "Bash(docker:*)",
      "Bash(docker-compose:*)",
      "Bash(docker compose:*)"
    ],
    "deny": [
      "Bash(docker run --privileged:*)"
    ]
  }
}
```

### mcp-ideate.json

```json
{
  "name": "mcp-ideate",
  "description": "Ideate plugin MCP tool permissions",
  "auto": true,
  "permissions": {
    "allow": ["mcp__plugin_ideate_ideate-artifact-server__*"]
  }
}
```

### mcp-cyberbrain.json

```json
{
  "name": "mcp-cyberbrain",
  "description": "Cyberbrain plugin MCP tool permissions",
  "auto": true,
  "permissions": {
    "allow": ["mcp__plugin_cyberbrain_cyberbrain__*"]
  }
}
```

### auto flag behavior

When `auto: true`, the init skill includes this rule module without presenting it in the selection menu. The user does not need to opt in. This is appropriate for MCP tool permissions that only matter when the corresponding plugin is installed — including them has no effect if the plugin isn't present, and saves a menu step.
