# 009: Create README.md

## Implementation Notes

### Structure

1. **Overview** (2 paragraphs)
   - What guardrail does: automates permission + sandbox config for Claude Code projects
   - The problem: constant permission prompts, accumulated one-off rules, no stack awareness
   - The solution: stack detection, generalized allowlists, OS-level sandboxing, audit tooling

2. **Quick Start** (3 steps)
   ```
   1. Install: add guardrail to your Claude Code plugins
   2. Navigate to your project directory
   3. Run /guardrail init
   ```

3. **Skills**
   - `/guardrail init` — what it does, example interaction showing the menu, what it writes
   - `/guardrail audit` — what it does, example report output, fix modes

4. **Included Stacks** (table)
   | Stack | Detection Files | Tools Allowed | Sandbox Domains |
   With all 6 stacks (_base, python, node, rust, go, shell)

5. **Included Rules** (table)
   | Rule | Description | Auto? |
   With all 5 rules (git, web, docker, mcp-ideate, mcp-cyberbrain)

6. **Customization**
   - Where to put custom stacks: `.claude/guardrail/stacks/`
   - Where to put custom rules: `.claude/guardrail/rules/`
   - Same-name files replace plugin defaults; new filenames are additive
   - JSON schema reference for both StackModule and RuleModule

7. **Key Knowledge**
   - Sandbox auto-allow mode: what it does, why it's enabled by default
   - Deny-always-wins: deny rules cannot be overridden by allow rules
   - Global vs local settings: how they interact, which takes precedence
   - What guardrail touches: only `permissions` and `sandbox` keys
   - What guardrail never does: modify global settings, delete non-permission config, write without confirmation

8. **How It Works**
   - Brief merge algorithm description
   - Override discovery (plugin root → project .claude/guardrail/)
   - Git repo detection for write location

9. **FAQ**
   - "Can I use this outside a git repo?" → Yes, it will ask where to write
   - "How do I undo?" → Restore from settings.local.json.bak
   - "Will this break my existing settings?" → No, it only touches permissions and sandbox keys
   - "What if sandboxing isn't available on my platform?" → Warning is shown, tighter permission rules compensate
