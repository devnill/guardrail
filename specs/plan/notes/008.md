### Skill Structure (three phases)

#### Phase 1: Load and Classify

Instructions for Claude to:

1. Read `~/.claude/settings.json` — extract `permissions.allow` and `permissions.deny`
2. Read `.claude/settings.local.json` — extract `permissions.allow` and `permissions.deny`
3. Read all stack and rule JSONs from `${CLAUDE_PLUGIN_ROOT}` to build reference patterns
4. Build the effective ruleset (what Claude Code actually evaluates)

Classification logic (instruct Claude to apply these heuristics to each rule in LOCAL settings):

**Generalizable:**
- Group rules by command prefix (the command name before the first space or `:`)
- If 3+ rules share a prefix AND the prefix is not on the safety deny list, flag them as generalizable
- Suggest consolidation to `Bash({prefix}:*)`
- Also flag individual rules that are strict subsets of a known stack/rule module pattern

**One-off / Session artifacts:**
- Contains hex strings longer than 8 characters (commit hashes, session IDs)
- Contains loop syntax fragments: `for `, `do `, `done`, `echo "=== $`
- Contains absolute paths to `/tmp/`, `/private/tmp/`, or temp directories
- Contains absolute paths to specific files that don't exist in the current project
- Contains pipe fragments that look like partial commands

**Redundant:**
- Rule is an exact duplicate of another local rule
- Rule is already present in global settings (exact match)
- Rule is a strict subset of a broader local or global rule (e.g., `Bash(git status:*)` when `Bash(git:*)` exists)

**Risky:**
- Matches patterns: `rm -rf`, `rm -r`, `sudo`, `curl * | sh`, `wget * | sh`, `--force`, `--privileged`, `--no-verify`
- Allows write to sensitive paths: `.env`, `.ssh`, `credentials`
- Very broad wildcards on dangerous commands

**Clean:**
- None of the above apply. Rule is well-scoped, unique, and non-dangerous.

**Safety deny list (never suggest wildcarding these):**
`rm`, `sudo`, `curl`, `wget`, `chmod`, `chown`, `kill`, `pkill`, `dd`, `mkfs`, `fdisk`

#### Phase 2: Report

Present findings in this structure:

```
## Audit Report: .claude/settings.local.json

**Total rules analyzed:** {N} (local) + {N} (global)

### Generalizable ({N} rules)
  Bash(git status:*) → consolidate to Bash(git:*)
  Bash(git add:*)    → consolidate to Bash(git:*)
  ...

### One-off / Session Artifacts ({N} rules)
  Bash(for id in af2eb7f6bb2e323aa...) — session-specific loop
  ...

### Redundant ({N} rules)
  Bash(python3:*) — already in global settings
  ...

### Risky ({N} rules)
  Bash(rm -rf:*) — allows recursive deletion
  ...

### Clean ({N} rules)
  Bash(pytest:*) — appropriately scoped
  ...

### Global Observations (informational)
  {Any findings about global settings — risks, generalizations possible, etc.}
  Note: guardrail does not modify global settings. These are observations only.

### Summary
  Recommended removals: {N}
  Recommended consolidations: {N}
  Requires manual review: {N}
```

#### Phase 3: Fix Options

After report, ask user:
1. **Fix all** — Apply all recommended changes, show result, confirm before write
2. **Fix one-by-one** — Step through each recommendation. For each: show the rule, the recommendation, and ask confirm/skip
3. **Export only** — Write report to `.claude/guardrail/audit-report.md`, no settings changes

Fix actions:
- Generalizable: replace group of specific rules with the generalized form
- One-off: remove the rule
- Redundant: remove the rule
- Risky: always ask individually even in fix-all mode — "Keep, modify, or remove?"
- Clean: no action

After all fixes applied, show the cleaned config and confirm before writing.

### Edge cases

- No local settings file: report "No .claude/settings.local.json found. Run /guardrail init first."
- No global settings file: skip global analysis, note in report
- Empty permissions arrays: report "No permission rules configured."
- All rules are clean: report clean bill of health, no fixes needed
